# RAG 评测与相关性阈值优化总结

评测日期：2026-10-21

## 目标

为“保知通”互联网保险售后知识助手建立可重复的 RAG 评测闭环，量化检索召回、引用质量、无依据问题拦截和风险问题人工升级效果。

## 评测集

- 知识问答集：42 题；其中 29 题有明确的标准资料来源，13 题为无依据问题。
- 无依据问题同时覆盖完全无关问题，以及保险领域但当前知识库未覆盖的问题。
- 风险拦截集：8 题，覆盖投诉升级、理赔争议、隐私风险和不当承诺。

每个知识题包含 `expected_sources`、`must_include` 和 `should_refuse`，评测数据与脚本均在本目录维护。

## 优化策略

### 1. 检索距离诊断

检索阶段记录最佳余弦距离。距离越小，问题与候选知识片段越相关。

| 问题类型 | 样本数 | 最小距离 | 中位数 | 最大距离 |
| --- | ---: | ---: | ---: | ---: |
| 有标准资料的问题 | 29 | 0.1961 | 0.3094 | 0.4430 |
| 无依据问题 | 13 | 0.3738 | 0.5004 | 0.6330 |

基于该分布，将 `RETRIEVAL_MAX_COSINE_DISTANCE` 设为 `0.45`。当最佳候选距离大于阈值时，检索层返回空结果，而非把语义上较远的资料交给模型生成答案。

### 2. 无证据安全答复

当 Agent 已调用 `search_knowledge`、但没有获得任何资料时，后端直接返回固定安全答复，并停止后续模型生成。普通接口与流式接口均实现相同逻辑，避免只依赖 Prompt 约束。

## 结果

### 检索与风险规则

| 指标 | 结果 |
| --- | ---: |
| Source Recall@3 | 82.3% |
| Strict Query Recall@3 | 79.3% |
| 检索引用精确率代理指标 | 32.2% |
| 无依据问题检索层拦截率 | 61.5% |
| 风险等级判断准确率 | 100.0% |
| 应人工升级问题的召回率 | 100.0% |
| 人工升级判断精确率 | 100.0% |

阈值上线后，42 题中的 8 条无依据问题在检索层直接被拦截；当前评测集上的 Source Recall@3 保持不变。

### 端到端 Agent

| 指标 | 结果 |
| --- | ---: |
| 最终回答引用召回率 | 91.2% |
| 最终回答引用精确率 | 24.0% |
| 有依据题关键事实覆盖率 | 82.3%（51/62） |
| 拒答场景安全答复率 | 94.7% |
| 成功执行题数 | 42/42 |

“有依据题关键事实覆盖率”只统计存在标准知识来源的问题；无依据题通过安全答复率单独衡量，避免把拒答文案差异误判为事实覆盖不足。

## 复现命令

离线检索与风险评测：

```bash
docker compose exec api python scripts/evaluate_rag_retrieval.py \
  --top-k 3 \
  --report docs/rag-evals/reports/retrieval-threshold-045.json
```

端到端 Agent 评测（调用配置的 LLM）：

```bash
docker compose exec api python scripts/evaluate_rag_retrieval.py \
  --top-k 3 \
  --with-agent \
  --report docs/rag-evals/reports/agent-threshold-045.json
```

## 当前限制与后续方向

- `0.45` 是基于当前知识库和评测集标定的阈值；新增知识或更换 embedding 模型后，需要重新评测。
- 仍有少量“语义相近但资料不足”的问题会通过距离阈值；目前由 Prompt、风险规则和人工确认提示共同约束，后续可增加基于引用的回答验证。
- 当前引用精确率是离线代理指标，且 Agent 会返回工具检索到的全部片段；后续可只展示最终答案实际使用的引用，进一步提升可解释性。

## 面试表达

我没有只做“上传文档 + 向量检索”的 Demo，而是给保险售后 RAG 建立了可重复评测集。先用距离分布标定检索阈值，再通过检索为空的后端硬兜底拦截无依据回答；最终同时量化召回、关键事实覆盖、风险升级和拒答安全性，并保留可复现报告。
